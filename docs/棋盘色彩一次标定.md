# 12×9 棋盘色彩一次标定

目标：取消 KEY2 / KEY3 黑白分次校准，通过 UART 采集棋盘后把固定参数编译进 FPGA 固件并保存于 Flash。后续每次开机直接加载同一组参数，不再从场景重新估计白平衡。

采集版已完成 RTL 回归、Efinity map/interface/pnr/pgm，以及 setup/hold 检查（最小 +0.027 / +0.026 ns），并写入 W25Q64 Flash、回读校验成功。首组六幅 CRC 验证图像取得五幅稳态有效样本；一幅亮度离群被剔除。补采组未包含棋盘，拒绝拟合。真实系数已写入源码，最终按键冻结版已通过构建与时序检查，已写入 Flash、回读校验成功，等待配置复位后的实板读取。

## 采集与参数含义

在 1920×1080、约 60.044 fps 通路上，KEY2 按键请求后，在下一完整显示帧从去马赛克后、白平衡/显示曲线前的线性 RGB 采集 96×54 缩略图。RAM 保存图像，后续实时画面不会覆盖；UART `C` 只读取已保存图像，直到再按 KEY2 才换成新的快照。未拍照时返回宽高为 0 的有效 CRC 包，主机拒绝使用。KEY3 校准功能取消；LED2 在快照完成后亮起。按键请求若遇到 UART 传输会排队，确保读取中不改写 RAM。不影响 DDR 或 HDMI 实时 1080p60 显示。数据包为 `IRISCAL1` + 小端 16 位宽/高 + RGB 字节 + 小端 CRC16-CCITT，初始化 `ffff`；主机必须验证 CRC 后才能拟合。

棋盘使用 12×9 实际方格，正对镜头、覆盖超过 75% 的画面，使用未来常用照明。中央 ROI 内聚类黑白两类，剔除方格边缘、明显梯度和截断高光，检查空间交替、两类样本数，以及连续多帧白格稳定性。采样原始数据、PNG 和拟合结果保存在验证目录，任何质量拒绝均不写入最终参数。

黑格会反射光，不能作为传感器物理黑电平。当前拟合为显示对比度设置保守黑位：黑格映射到线性 8/255、漫反射白格映射到线性 180/255；从两组 RGB 中值解出逐通道显示黑位及 Q8 增益，黑位限制 0–48 个 RAW8 等级；把漫反射白格映射到线性 180/255，以保留高光余量。三通道 Q8 增益同时调节白平衡和显示亮度，限制在 0.5–3 倍。显示继续使用已有 sRGB / S 曲线与适度色度增强。参数是此棋盘和照明下的显示基准，不能据两个颜色恢复完整 CCM、响应曲线或严格色准；照明色温明显变化时，固定白平衡也可能偏色。

参数模块为 `iris_ws/src/video/debayer/camera_colour_profile.v`，原按键白平衡控制器从顶层移除；KEY0 / KEY1 保留曝光 agent 当前的曝光补偿方案。已纠正其曝光半行编码并检查 I2C group-hold、曝光上下限，以保持原生 60 fps。

## 验证

- 实际 UART 解码验证两次采集命令、采样位置/顺序、RGB 三通道、CRC，传输期间其他帧数据不会污染已冻结图像。
- 主机拟合测试验证合成棋盘的中性白色，以及非棋盘分区墙面、过曝和曝光漂移拒绝。
- 全部现有视频、DDR 完整帧发布、曝光编码、UART、OSD 回归通过。

实板数据、最终 Flash 校验、60 fps 与画面复验将在标定完成后补充。


## 本次实测参数

五幅有效图像的白格 RGB 中值为 119 / 174 / 83，黑格为 25 / 30 / 23。最终 Q8 增益为 **470 / 305 / 731**（1.83594 / 1.19141 / 2.85547 倍），显示黑位为 **21 / 23 / 20**。参数保存在 `camera_colour_profile.v`，从参考照明下的棋盘数据取得；软件复现已有显示曲线的修正图保存在 `capture-01/corrected-view.png`。

用户随后要求按键决定采集时刻：KEY2 只采集、冻结图像；UART 读取不再重新采集，也不会改动固定色彩参数。图片在 FPGA RAM 中，重启后清空；色彩参数则编译进 Flash 固件，重启仍保持。

读取所拍图像：`python3 .script/calibrate-checkerboard --frames 1 --read-only --directory <保存目录> --profile docs/validation/20261003-checkerboard/capture-01/profile-measurement.json`。原始线性 RGB、CRC 包、原显示曲线预览和固定参数修正预览均保存。重复读取同一幅冻结照片不能当作多幅独立标定数据，拟合脚本会拒绝这种情况。


最终按键冻结版 Efinity map/interface/pnr/pgm 全部通过，setup 最小 +0.011 ns、hold 最小 +0.026 ns。最终回归验证未按键时空响应、按键决定采集时刻、实时场景改变后的重复读取仍保持原图、再次按键明确替换，以及 RGB/CRC。固件保存在 `firmware/video-checkerboard-fixed-20261003/`，对应 `final-*` 构建、Flash、源码和时序证据。


## 最终实板复验

固定参数及按键冻结固件已从 Flash 启动。用户短按 KEY2 后，串口两次完整读取同一幅 96×54 棋盘图，CRC 均通过、RGB SHA-256 完全相同：`3cd0736ec1f07999f98286e6cc08bb2f00c50f5b88f7e38403f39e3a1ecd97a3`。棋盘确实保存在快照中，后续画面没有覆盖；原始包/RGB、原预览、参数修正预览位于 `key-snapshot/`。放大的预览是 96×54 采样的整数放大，用于看色调，不代表 HDMI 的 1920×1080 清晰度。

复验 15 秒串口得到 12 份完整报文，CAM 与 DDR 完整帧 WR 全部为 60 fps，HDMI 60–61 fps；帧周期对应 60.04383–60.04390 fps，HTS=1622、VTS=1150、原生尺寸 1920×1080。采集按键及固定色彩处理未破坏已验证的 1080p60 通路。最终实板摘要为 `final-validation.json`，运行原始报文为 `final-uart.log`。
