# 1080p60 / 4K30 YCbCr420 双模式

2026-10-03。两种模式存储在同一份 Flash 固件中，默认上电为 1080p60。

| 模式 | 摄像头原生采集 | HDMI 图像尺寸 | 输出格式 | 标称实际刷新率 |
|---|---|---|---|---|
| 默认 | 1920×1080，约 60.044 fps | 1920×1080 | RGB888，原有 DVI/TMDS 通路 | 约 60.10 Hz |
| KEY3 切换后 | 1920×1080，约 60.044 fps | 3840×2160 | YCbCr 4:2:0，8-bit，BT.709 有限范围 | 约 30.05 Hz |

4K 图像来自原生 1080p 图像的两倍放大，不是原生 4K 采集。这里采用的是色度采样格式，不是 H.264/H.265 编解码。当前接入的显示器不支持 4K30，因此本次实板验证范围是 FPGA 内部输出时序和模式切换，4K 显示兼容性及可见画质尚未验证。

## 使用

- KEY3：短按切换两个模式。请求在显示读帧的 VS 上升沿提交；切换分辨率时显示器可能重新同步。
- KEY2：保留棋盘采样拍照和串口重复读取功能；LED2 表示照片就绪。
- KEY0 / KEY1：保留曝光补偿。固定色彩参数保持不变。
- LED3：亮表示 4K30 4:2:0 模式，灭表示 1080p60 RGB 模式。
- 串口 115200：ASCII `4` 选择 4K 模式，ASCII `1` 返回 1080p。上电不会记住上一次选择。

串口诊断增加 `M=0/1 O=780x438/F00x870`，尺寸字段为十六进制。尺寸来自最终输出 DE/VS 的测量；4:2:0 每个 TMDS 字承载两个亮度像素。CAM、WR、HDMI 的帧率仍分别计数。

```sh
python3 .script/read-video-status --mode 4k --seconds 12 --output /tmp/iris-4k
python3 .script/read-video-status --mode 1080 --seconds 7 --output /tmp/iris-1080
```

## 实现与性能边界

两种模式均使用现有 148.75 MHz TMDS 字时钟和 1.4875 Gbit/s/通道的串行输出，不切换 PLL。4K 模式将 DDR 显示读出调整为 1080p30，原生采集和完整帧写入继续约 60 fps。三帧银行的读锁和最新完整帧发布逻辑保持原实现。

放大器保存两行完成的 RGB→YCbCr 像素数据，共 92,160 bit。每个源像素成为一个 2×2 块，两个 Y 样本相同；第一行发送 Cb，第二行发送 Cr。读写银行交替，并检查完成行的序号；未完成的行输出有限范围黑色，不读取未初始化 RAM。

HDMI 新增 AVI InfoFrame v3，VIC95，BT.709、有限范围、4:2:0，以及视频/数据岛前导码、保护符和 BCH 校验。原有 RGB 编码器保留。显示器必须明确支持该模式，当前实现没有自动读取输出端 EDID。

行缓存放大的处理延迟约为一条源行（29.6 μs），去马赛克的额外栅格延迟约 14.8 μs；两者合计约 44.4 μs 为时序计算值。实际端到端延迟仍包含 DDR 帧等待、30 Hz 刷新和显示器处理，本次没有测量。30 Hz 每帧间隔约 33.3 ms，运动流畅度低于 60 Hz。

## 已完成检查

- 既有 RAW/BGGR、固定色彩、曝光、OSD、帧银行、写提交、传感器读回、KEY2 拍照回归通过。
- 增加双倍水平消隐的去马赛克测试，检查完整三帧、边界和最后一行。
- 1,536 个灰阶/原色/黄色/混合色样本与浮点 BT.709 参考比较，误差不超过一码；灰阶保持中性，输出在有限范围内。
- 放大器检查完整帧、行数、2×2 映射、Cb/Cr 行序、行周期和模式重启后的旧帧抑制。
- HDMI 实际发送符号解码验证 AVI 头、校验和、五个 BCH 块、TERC4、前导码、保护符和 1,920 个有效视频字。
- 异步模式请求只在 VS 上升沿提交，VS 高电平期间及有效帧内不提交。
- Efinity map / interface / pnr / pgm 通过；最小 setup 裕量 +0.010 ns，hold +0.024 ns。
- 设计已写入 Flash 地址 0，回读报告 `Flash verify successful`；用户重启后串口确认新固件启动。

模式切换后的第一个 1 秒帧率计数窗口可能混合两种帧率，验证稳定值时舍弃头两个串口样本。没有把瞬态读数当作稳定帧率。

全部实测记录保存在 [验证目录](validation/20261003-dual-output/)，最终往返测试统计见 [switch-summary.json](validation/20261003-dual-output/switch-summary.json)。本次未使用支持 4K30 的显示器或 HDMI 分析仪；串口数据不等同于外部接收端成功显示。

## 本次实板读数

Flash 重启后，默认模式读到 `M=0 O=780x438`，即 1920×1080，HDMI 60 fps。第一次切至 4K 的混合计数窗口为 42 fps，随后保持 30–31 fps，`M=1 O=F00x870` 对应 3840×2160。

通过串口进行了三轮完整往返，五段后续采集中有 18 份舍弃瞬态后的稳定样本：4K 尺寸均为 3840×2160，HDMI 为 30–31 fps；1080p 尺寸均为 1920×1080，HDMI 为 60–61 fps。摄像头和写入维持 60–61 / 60 fps。最后再读取确认板卡停留于 1080p60，传感器周期对应 60.04383–60.04390 fps。

按键映射与 VS 提交逻辑已经实现并仿真；此次往返使用串口请求同一模式状态机，未由人手实际按 KEY3。4K 外部画面和端到端延迟未作实测。完整摘要见 `validation/20261003-dual-output/validation.json`。
