# 相机低增益曝光恢复

用户报告共享相机源持续出现细小彩色闪烁颗粒，并读到十六进制
`E=200..410 G=A`。现有增益表中 A 对应约 24.640 倍模拟增益，曝光为
512..1040 半行，存在延长曝光的余量。旧 AE 在变亮后先减曝光，可能保留高增益。

本版只在 `ae_ctrl.v` 增加增益／曝光配平：有余量时降低一档增益并按比例延长
曝光，用同一个 7 次写入的 group hold 原子提交。原曝光范围、增益表、目标亮度
及写后等待帧数保留。既有 RAW 同色中值／截限平滑和 RGB 3×3 高斯保留。
HDMI 仍为 1080p；AI 参数、模型、固件和原采样分支审计见
`ai-rollback-audit.json`，各项比对通过。

`ae-rtl.log` 验证原曝光寄存器契约及带两帧反馈延迟的明暗切换。用户读数的
等效亮度场景恢复到 G=6..8，18 个配平组中曝光×增益变化小于 0.5%，恒定
场景不反复调节，真正暗场仍可使用 G=A。此为控制逻辑仿真，不能代替图像验收。

`build-identity.json` 绑定实际加载的位流；最终 setup 最小余量 +0.019 ns，
hold +0.003 ns，23 组时钟关系均通过。RAM 256/256，DSP 114/160。
只通过 `.script/sync-iris jtag` 加载 SRAM，未写 Flash。此前可运行版本备份于
`/tmp/iris-before-low-gain-ae-20261016/`。

`live-report.json` 为无 JTAG 暂停的 120 秒串口观测：实际提交约 30.052 FPS，
欠载、读取错误及拒绝均为 0。AI 正常刷新。`acceptance.json` 的画质验收仍为
待定；等待用户反馈新 E/G、左侧彩色雪花和运动拖影。曝光延长可能增加运动
模糊，未实施跨帧降噪或几何防抖。
