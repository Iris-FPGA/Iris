# 彩色轮廓显示与调参

2026-10-17：针对“左侧彩色、右侧黑白；改参数变化不明显”的显示修复。

## 为什么原来接近黑白

当前学生 CNN 学的是浅色线稿，导出的 RGB 本身接近粉白色。旧 `render()`
又通过 `base=255-((255-minimum+2)>>2)` 把最暗通道抬到接近白色，
其余通道很容易一起裁剪到 255。最后对 RGB 减去相同的轮廓压暗量，
因此画面主要剩下白底和灰黑线。调梯度阈值只能改变线条，无法恢复物体颜色。

`SCALE_Q24` 是神经输出的**反量化比例**，当前模型要求 20596120，
并由 `iris_ws/iris_ws.xml` 的 `STYLE_SCALE_Q24` 经顶层逐级覆盖。
它不是画风或饱和度旋钮；只改 `iris_style_contour.v` 的同名默认值不会改变工程配置。

## 新显示路径

默认 `h`/模式 2 使用同一 DDR 银行、同一行列的相机 RGB 与 CNN RGB 混合，
再增强色度、减少颜色级数，最后叠加平滑主轮廓。默认相机占 75%、CNN 占 25%。
这属于显示端混合风格，原始 CNN 张量、推理权重和量化参数保持原值；
颜色恢复来自相机，不能据此声称 CNN 已重新学会彩色风格。

左侧当前为原生相机直通，原先缓存左半原图的 RAM 不参与可见显示。
新版将原来的 1024×96 缓存改成两份 512×96，分别保存右半 CNN RGB 与
右半同帧相机 RGB。灰度邻域继续使用完整 640 列；不增加 DDR 读事务。
默认构建的颜色 RAM 总位数保持不变，面板总延迟仍为 7 个双像素时钟。
如果单独启用 `NATIVE_CAMERA_LEFT=0` 的旧显示回归，则会保留左半缓存，
该可选配置需要额外颜色 RAM，不能套用默认配置的资源结论。

## 先调颜色，再调线条

直接修改 `iris_ws/src/cnn/iris_style_contour.v` 开头的参数，每次只改一项。

| 参数 | 当前值 | 建议调法 |
|---|---:|---|
| `SOURCE_MIX_Q2` | 3 | 0..4，对应相机占比 0%、25%、50%、75%、100%。颜色太淡先保持 3；希望更像神经原画可试 2。0 无法补回模型丢失的颜色。 |
| `SATURATION_Q2` | 5 | 4=原饱和度，5=1.25 倍，6=1.5 倍。偏灰试 6；过艳试 4。灰阶仍为中性。 |
| `COLOUR_BITS` | 5 | 每通道 32 级。4=16 级，色块感更明显；6=64 级，更柔和；8=关闭色阶化。 |
| `NORMAL_THRESHOLD` | 20 | `h` 的轮廓门槛，保留你本轮的修改。杂线多时依次试 32、48、64；线条少时降低。 |
| `NORMAL_INK_GAIN` | 2 | 门槛以上的加深速度。默认 2；希望更重可试 4。 |
| `NORMAL_INK_CAP` | 128 | 最多压暗多少，范围 0..255。线条过黑先试 96；更重可试 160。 |
| `STRONG_THRESHOLD/INK_GAIN/INK_CAP` | 40 / 4 / 160 | 只影响 `s`/模式 3，用于更重的主轮廓。 |

建议顺序：先使用默认值确认红绿蓝物体能显示颜色；然后比较
`SATURATION_Q2=4/5/6`；再比较 `COLOUR_BITS=4/5/6`；最后调阈值去除杂线。
两档共用颜色参数，`NORMAL_*` 仅作用于 `h`，`STRONG_*` 仅作用于 `s`。
修改阈值后，压暗量始终按 `clip((gradient-threshold)*gain,0,cap)` 饱和，
不再出现旧阈值修改后斜坡超过封顶值的情况。

| UART 单字符 | 显示 |
|---|---|
| `n` | 原始 CNN 颜色，供诊断，仍可能很淡 |
| `c` | 原始 CNN 对比度增强 |
| `h` | 彩色轮廓，默认 |
| `s` | 彩色轮廓，加重主线 |

UART 需以原有固件运行方式发送单字符，切换在 VS 边界生效。
Verilog 参数是编译期参数，编辑后需要重新编译并加载位流。

## 先离线预览，避免盲目烧录

以下命令读取已经保存的硬件输入/输出，不操作板卡。默认参数自动读取当前 RTL。

```sh
python3 .script/render-style-visibility.py \
  docs/validation/20261016-camera-median/diagnostic \
  --contour --mode 2 --compare \
  --output /tmp/iris-colour-default.png

# 仅改变预览参数，不修改 RTL；满意后把参数写回 Verilog。
python3 .script/render-style-visibility.py \
  docs/validation/20261016-camera-median/diagnostic \
  --contour --mode 2 --source-mix-q2 3 --saturation-q2 6 \
  --colour-bits 4 --threshold 32 --ink-gain 2 --ink-cap 128 \
  --compare --output /tmp/iris-colour-blocks.png
```

四栏依次为采集原图、原始 CNN、修改前轮廓、新彩色轮廓。
示例保存在 `docs/validation/20261017-style-colour/colour-comparison.png`。
这些是同帧离线显示参考，不能代替新位流的实屏验收。
