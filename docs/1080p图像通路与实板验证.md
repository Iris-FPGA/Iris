# 1080p 图像通路与 Flash 验证记录

本记录对应 2026-10-02 的图像质量与帧缓存修复。早期接入纪要中的灰度抽样、720p 参数和未加载 SDC 的描述不代表当前源码。

## 已实现

- 传感器输出窗口 1920×1080 RAW10；DDR 保存每像素高 8 位，显示为原生 1080p 彩色图像。
- RAW 四像素打包按实际扫描顺序进入 DDR，读出的两个像素不再交换字节。
- BGGR 双像素双线缓存去马赛克，3×3 双线性插值，四边同色镜像延拓；控制信号与 RGB 一起延迟。
- 自动白平衡统计取线性 RGB，显示侧执行饱和增益与 sRGB 转换，防止线性 RAW 直接输出到显示器导致中间亮度偏暗。
- HDMI 的 CAM 行显示实际采集尺寸、传感器帧率和 DDR 完整帧写入率 WR；HDMI 行独立测量输出尺寸与刷新率。曝光 agent 的 AE 显示和控制仍保留。

HDMI 总时序为 2200×1125，像素时钟 148.75 MHz，因此实际刷新约 60.10 Hz。帧率为一秒计数，可能显示相邻整数。

## 分块及色块闪烁修复

原 `ddr_buffer.v` 固定 bank 间距 `0xE2000` 只有 925,696 字节，1920×1080 RAW8 一帧需要 2,073,600 字节，跨 bank 覆盖。现由 `frame_bank_manager.v` 按尺寸计算间距，4 KiB 向上对齐后再留 4 KiB 保护空间：

| bank | 起始地址 | 间距 |
|---|---:|---:|
| 0 | 0 | 2,080,768 (`0x1FC000`) |
| 1 | 2,080,768 | 同上 |
| 2 | 4,161,536 | 同上 |

读端在 DDR 读模块实际锁存地址的同一拍锁定完整帧，写端跳过被读端占用的 bank；读写切换同拍也遵守此约束。`frame_buffer.v` 将最大图像尺寸传给内部 DDR 模块。

## 验证与限制

RTL 回归均通过：RGGB/BGGR 三种图像的连续三帧逐像素及控制时序检查；256 输入灰度×6 增益的 RGB/sRGB 检查；带 valid 间隙的 1920×1080 采集及模式变化；OSD 数字、字形和图像透传；三 bank 非重叠、写快于读和同时切换压力测试。

```sh
python3 tests/video/run_video_tests.py   # 需要 Icarus Verilog；支持 IVERILOG/VVP/IVERILOG_LIB 环境变量
.script/build-iris
.script/sync-iris                      # 默认 JTAG bridge → SPI Flash
```

Efinity 2026.1 的 map、interface、pnr、pgm 全通过，实际加载项目 SDC。输入时钟先定义再应用 PHY/UART 延迟；跨 FIFO 的域使用异步时钟组。最终时序报告所列 setup/hold 余量均为正，最小 setup 余量仅 +0.001 ns（DDR IP 内部跨域 Gray 指针），不能由此推断实板长期稳定性。

用户在前一版实屏测得 CAM 1920×1080、30–31 fps，WR 30，HDMI 1920×1080、60 fps。摄像头原生 60 fps 尚未验证，也不能把 HDMI 重复显示同一帧算作 60 fps 采集。当前 HTS=1800、VTS=1150 没有达到目标；后续需核实传感器寄存器回读、时钟及 60 fps 初始化表。

## 2026-10-03：完整帧发布与曝光位域

继续检查发现两处实际接口错误，上一轮 bank 管理仿真只提供理想完成脉冲，未覆盖真实 DDR 写模块的输出，因此没有检出第一处问题。

1. `ddr_wr_buffer.v` 原 `bank_sw = burst_last`：`burst_last` 在最后一个 burst 的整个传输过程中保持高电平。bank 管理每拍都会据此发布和切换，既重复发布，也没有等待最后一段写完。现等待最后一个 W 数据拍与全部 B 响应完成，只输出一次完成脉冲。
2. `ae_ctrl.v` 曝光位域原为 `3e00=exp[11:8], 3e01=exp[7:0]`，传感器实际解码为 `{3e00[3:0],3e01,3e02[7:4]}`。512 半行被编码为 8192 半行，超出 VTS=1150 对应的 2289 半行上限。现为 `3e00=0, 3e01=exp[11:4], 3e02={exp[3:0],4'b0}`。保留曝光 agent 最新的手动按键调整方案。

新增回归均通过：真实 DDR 写模块的地址及像素顺序、最后一段 80 拍停顿、延迟 B 响应、连续三帧单次发布；真实曝光控制模块的 I2C group-hold、4 至 2289 半行范围和按键控制。临时恢复旧写法时，前者在只完成 256/320 个数据字、收到 1/3 个 B 响应时检出提前发布；后者检出 `0x220` 被写成 `0x2200`。

本轮使用 `/tmp/iris-quality-tools/video-timing-snapshot/iris_ws` 固定源码快照编译，避免公共 outflow 文件被并发构建改动。构建与烧录脚本支持 `IRIS_PROJ_DIR` 指定同一项目目录。实屏消闪、采集帧率及延迟仍需这一版 Flash 启动后确认。
