# 网页版运行手册（不用 SSH）

> 全程在**浏览器**里操作：JupyterLab 或 VSCode 的网页终端。
> 平台：算力自由 [gpufree.cn](https://www.gpufree.cn/)

---

## 为什么这份手册和上一份不一样

上一份 `运行手册.md` 是按 SSH（`ssh root@IP -p 端口`）写的。
既然你走网页，改动只有**取代码的方式**——其余命令完全一样：

| | SSH 版 | **网页版（本文）** |
|---|---|---|
| 取代码 | `scp` 传 43 KB 的 tar 包 | **`git clone` 一条命令**（fork 是公开的） |
| 终端 | 本机终端 | JupyterLab / VSCode 网页终端 |
| 断线风险 | 低 | **高 → 必须用 tmux**（见第 3 步） |

`deploy/scripts/cloud-up.sh` 是 SSH 专用的，你**不需要**它。

---

## 0. 开实例

控制台 → 算力市场 → 选卡 → 立即创建。

**建议先用「无卡模式开机」**（关机状态下可用，价格更低）把第 1~4 步做完：
装环境、拉素材、下 COCO、抽子集——这些都不需要显卡。跑训练前再关机、正常开机。

> 平台只在**「运行中」**计费；关机数据保留（数据盘）。

---

## 1. 打开网页终端

- **JupyterLab**：`File → New → Terminal`
- 或 **VSCode**：平台文档里有专门的 VSCode 接入说明

打开后确认自己在数据盘上：

```bash
cd /root/gpufree-data && pwd && df -h . | tail -1
```

> `/root/gpufree-data` 是平台的**数据盘**（默认 100G，可扩，关机不丢）。
> `/` 是系统盘（30G，**实例释放即删**）——大文件别放系统盘。

---

## 2. 取代码（一条命令）

```bash
cd /root/gpufree-data && git clone -b dev/tinyml https://github.com/hyperle/Iris-1.git Iris
```

代码就在 `/root/gpufree-data/Iris/deploy/`。

<details>
<summary>clone 太慢？</summary>

平台有「GitHub 加速」文档，按那里的方法配置代理；或者退而求其次用**浏览器上传**：

1. 本机跑 `deploy/cloud/pack.sh` 生成 43 KB 的 `deploy_code.tar.gz`
2. JupyterLab 左侧文件树拖进去上传
3. 网页终端里 `mkdir -p /root/gpufree-data/Iris && tar -xzf deploy_code.tar.gz -C /root/gpufree-data/Iris`

</details>

**以后要更新代码**：

```bash
cd /root/gpufree-data/Iris && git pull
```

---

## 3. ⚠️ 进 tmux（这一步别省）

网页终端的会话**会断**：浏览器标签关了、电脑睡眠、网络抖一下，终端里跑的进程就没了。
训练要跑几小时，必须先套 tmux（[平台 tmux 文档](https://www.gpufree.cn/docs/guide/apps/tmux.html)）。

```bash
tmux new -s train
```

- 断开（训练继续跑）：`Ctrl+b` 然后按 `d`
- 回来看：`tmux attach -t train`
- 看有几个会话：`tmux ls`

**之后第 4~6 步全部在 tmux 里执行。**

---

## 4. 一键准备 + 冒烟

```bash
bash /root/gpufree-data/Iris/deploy/cloud/web_quickstart.sh \
     --dataset /root/gpufree-data/coco/train2014
```

它会依次：定位路径 → 环境自检 + 拉风格图/90 张校准图 → 抽 1 万张子集 → 查 GPU → 跑冒烟。

**期望结果**：7 个步骤全跑完、`门禁 通过`、生成 `results.csv`。

> 如果 COCO 还没下，先看第 5 步；`web_quickstart.sh` 会跳过子集和冒烟并提示你。

---

## 5. 下 COCO（如果用全量）

```bash
mkdir -p /root/gpufree-data/coco && cd /root/gpufree-data/coco
# 全量 13 GB。平台有 HuggingFace 加速文档，走 HF 镜像通常快很多
wget -c http://images.cocodataset.org/zips/train2014.zip
unzip -q train2014.zip && rm train2014.zip
```

解压后是 `train2014/*.jpg`，所以 `--dataset` 要指向它的**父目录**：
`--dataset /root/gpufree-data/coco`（`ImageFolder` 语义：再往里一层才是图片）

---

## 6. 跑网格

**先小规模摸 `style_weight` 方向**（1 万张子集，几十分钟）：

```bash
cd /root/gpufree-data
./Iris/deploy/cloud/run_batch.sh --dataset /root/gpufree-data/coco10000 \
    --out /root/gpufree-data/runs/grid
```

看 `results.csv` 里哪个 `style_weight` 方向对，再改 `Iris/deploy/cloud/configs.tsv` 挑 2~3 个跑全量：

```bash
./Iris/deploy/cloud/run_batch.sh --dataset /root/gpufree-data/coco/train2014 \
    --out /root/gpufree-data/runs/full --only c16b3
```

> ⚠️ **`style_weight` 必须重扫**：`InstanceNorm` 换成 `BatchNorm` 之后风格强度一定会变，
> 原来那个 `1e10` 是配 IN 扫出来的，直接沿用大概率偏弱或偏强。

常用参数：

```bash
--only <正则>        只跑名字匹配的配置
--limit N            只跑前 N 行
--force              重跑已完成的（默认跳过）
--size 160x120       导出/量化的部署分辨率（默认 128）
--res-in-parallel 32 资源估算报哪个并行度（默认 16）
```

## 7. 看结果 / 拿出来

```bash
# 终端里直接看汇总表
column -s, -t /root/gpufree-data/runs/grid/results.csv | head -20
```

拿出来（**浏览器下载**，不用 SSH）：

1. 打包：

```bash
cd /root/gpufree-data/runs/grid
tar -czf /root/gpufree-data/grid_results.tgz results.csv *_int8.tflite *_compliance.md *_stylized.jpg
```

2. JupyterLab 左侧文件树 → 进 `gpufree-data` → 右键 `grid_results.tgz` → **Download**

> 权重（`runs/*/epoch_*.model`）不用拿，留在云上就行。

## 每个配置产出什么

```
<out>/
├── results.csv                   # 汇总（含 LUT/M10K/DSP 资源估算列）
├── logs/<name>.log               # 7 个步骤的完整日志
├── runs/<name>/epoch_*.model     # 权重
├── <name>_int8.tflite            # ← 交付物
├── <name>_compliance.md          # 算子合规报告（G2/G3）
├── <name>.resource.json          # 资源估算（G5）
├── <name>.equiv.json             # PSNR/SSIM（G4）
└── <name>_stylized.jpg           # 风格化样图（肉眼看）
```

`results.csv` 列：
`name, channels, blocks, params, macs_per_px, epochs, seconds, non_whitelisted_ops,
gate, res_lut, res_m10k, res_dsp, res_in_parallel, psnr_quant_db, ssim_quant,
psnr_e2e_db, ssim_e2e, tflite_kb, status`

## 常见问题

| 现象 | 处理 |
|---|---|
| 终端里训练跑一半没了 | 没用 tmux。重来一次，先 `tmux new -s train` |
| `缺少 STYLE_IMAGE，请先跑 bootstrap` | `web_quickstart.sh` 没跑完，或 `Iris/deploy/cloud/env.sh` 没生成 |
| `该目录下没有子文件夹` | `--dataset` 传的是父目录，不是 `train2014` 本身 |
| `CUDA 不可用` | 当前是「无卡模式开机」。关机 → 正常开机 |
| 磁盘满了 | 数据盘默认 100G；`df -h /root/gpufree-data` 看，必要时在控制台扩容 |
| 想边跑边看进度 | `tail -f /root/gpufree-data/runs/grid/logs/<name>.log` |
| 表头被当成一个配置 | 已加校验会自动跳过；表头请用 `#` 注释 |
| 训练报 `modified by an inplace operation` | 已修（`utils.py` 的 `normalize_batch` 改非原地）——如果还报，说明你 `git pull` 的不是最新 |
