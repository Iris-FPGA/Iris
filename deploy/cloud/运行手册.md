# 算力自由（gpufree.cn）运行手册

> 队友用的就是这个平台。证据：`examples@Iris:fast_neural_style/script/para.py:3` 的
> `/root/gpufree-data/...`，以及一个误提交的 vim swap 文件
> `.onnx2tf.py.swp` 里写着的 `root@gpufree-container`。
> 官方文档确认 `/root/gpufree-data` 就是**数据盘挂载点**：
> [开发机实例](https://www.gpufree.cn/docs/guide/instance/)、[快速开始](https://www.gpufree.cn/docs/guide/quick_start.html)

---

## 路径约定（照抄队友的布局）

| 用途 | 路径 | 说明 |
|---|---|---|
| 数据盘（持久） | `/root/gpufree-data` | 默认 100G、可扩；**关机数据还在，释放实例才删** |
| 系统盘 | `/` | 30G，实例释放即删 —— **大文件别放这** |
| 我们的代码 | `/root/gpufree-data/deploy` | 解开 `deploy_code.tar.gz` |
| 素材（风格图+校准图） | `/root/gpufree-data/examples` | `bootstrap.sh` 自动 clone |
| COCO 全量 | `/root/gpufree-data/coco/train2014` | 13 GB |
| 训练子集 | `/root/gpufree-data/coco10k` | `make_subset.py` 生成 |
| 跑批结果 | `/root/gpufree-data/runs/batch` | `results.csv` + 每个配置的产物 |

> 队友当初是放在 `/root/gpufree-data/FPGA/examples`，我们放 `/root/gpufree-data/deploy`
> 和 `/root/gpufree-data/examples`，互不干扰。

## 阶段 A：**无卡模式开机**（不烧卡时，把准备工作全做完）

平台支持"无卡模式开机"——不开 GPU 也能进容器。下面这些都不需要显卡：

### A1. 传代码（本机执行，32 KB）

```bash
deploy/cloud/pack.sh
rsync -avP deploy/cloud/deploy_code.tar.gz <user>@<host>:/root/
```

平台文档里有 rsync 专页，推荐用它（断点续传）。

### A2. 云端解开

```bash
mkdir -p /root/gpufree-data && cd /root/gpufree-data
tar -xzf /root/deploy_code.tar.gz      # 解开是 train/ quant/ verify/ env/ cloud/
mv train quant verify env cloud deploy_tmp 2>/dev/null
mkdir -p deploy && mv deploy_tmp/* deploy/ && rmdir deploy_tmp
export DEPLOY=/root/gpufree-data/deploy
```

### A3. 环境自检 + 拉素材

```bash
$DEPLOY/cloud/bootstrap.sh --dataset /root/gpufree-data/coco
```

它会：查 Python/依赖 → 拉 `FinResect/examples@Iris`（风格图 + 90 张校准图）→
检查数据集目录层级 → 生成 `cloud/env.sh`。

> 缺 torch 时它**只告警不自动装** —— 云镜像自带的是匹配驱动的 CUDA 构建，
> 从 PyPI 装会拉成不匹配的版本。

### A4. 下 COCO（或先下子集）

```bash
mkdir -p /root/gpufree-data/coco && cd /root/gpufree-data/coco
# 全量（13 GB）；平台有 GitHub/HuggingFace 加速文档，走 HF 镜像通常快很多
wget -c http://images.cocodataset.org/zips/train2014.zip
unzip -q train2014.zip && rm train2014.zip
```

### A5. 抽子集（**建议第一次这么干**）

```bash
$DEPLOY/.venv/bin/python $DEPLOY/cloud/make_subset.py \
    --src /root/gpufree-data/coco/train2014 \
    --dst /root/gpufree-data/coco10k --num 10000 --val-num 8
```

默认硬链接，不额外占盘。之后 `--dataset` 传 **`/root/gpufree-data/coco10k`**
（父目录），不是 `.../coco10k/train2014`。

## 阶段 B：开卡，跑训练

### B1. 确认 GPU 认到了

```bash
python3 -c "import torch; print(torch.__version__, torch.cuda.is_available())"
nvidia-smi --query-gpu=name,memory.total --format=csv,noheader
```

### B2. 冒烟（1 配置 / 1 epoch / 64×64）—— 只为验证链路

```bash
cd /root/gpufree-data
$DEPLOY/cloud/run_batch.sh --smoke
```

期望：7 个步骤全跑完、`门禁 通过`、`results.csv` 生成。

### B3. 小规模网格（子集，摸 `style_weight` 方向）

```bash
$DEPLOY/cloud/run_batch.sh --out /root/gpufree-data/runs/grid10k \
    --dataset /root/gpufree-data/coco10k
```

> ⚠️ `--dataset` 是 run_batch 的选项，会覆盖 `env.sh` 里的值。
> 注意 `style_weight` **必须重扫**：InstanceNorm 换成 BatchNorm 之后风格强度会变，
> 队友原来的 `1e10` 是配 IN 扫出来的。

### B4. 全量训练

看 `results.csv` 里哪个 `style_weight` 方向对，改 `cloud/configs.tsv` 挑 2~3 个配置：

```bash
export DATASET=/root/gpufree-data/coco/train2014   # 或直接改 env.sh
$DEPLOY/cloud/run_batch.sh --out /root/gpufree-data/runs/full \
    --dataset /root/gpufree-data/coco --only c16b3
```

**先跑一个 epoch 看耗时再决定跑多少**（B2 的日志里有单 epoch 时间）。

---

## 阶段 C：收工

```bash
# 只把结果拿回来（权重不用拿，云上留着）
cd /root/gpufree-data/runs/full
tar -czf /root/gpufree-data/batch_results.tgz results.csv *_int8.tflite *_compliance.md
```

本机：

```bash
rsync -avP <user>@<host>:/root/gpufree-data/runs/full/{results.csv,*.tflite,*.md} deploy/out/
```

然后**关机**（平台只在"运行中"计费；关机数据保留）。

## 每个配置产出什么

```
<out>/
├── results.csv                   # 汇总（含资源估算列）
├── logs/<name>.log               # 7 个步骤的完整日志
├── runs/<name>/epoch_*.model     # 权重
├── runs/<name>/train_config.json # 结构/超参/种子/参数量
├── <name>_int8.tflite            # ← 交付物
├── <name>_compliance.md          # 算子合规报告（G2/G3）
├── <name>.gate.json              # 机器可读
├── <name>.resource.json          # 资源估算（G5，官方 resource_lib）
├── <name>.equiv.json             # PSNR/SSIM（G4）
└── <name>_stylized.jpg           # 风格化样图
```

`results.csv` 列：
`name, channels, blocks, params, macs_per_px, epochs, seconds, non_whitelisted_ops,
gate, res_lut, res_m10k, res_dsp, res_in_parallel, psnr_quant_db, ssim_quant,
psnr_e2e_db, ssim_e2e, tflite_kb, status`

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `缺少 STYLE_IMAGE，请先跑 bootstrap.sh` | 没跑过 bootstrap，或 `deploy/cloud/env.sh` 没生成 |
| `该目录下没有子文件夹` | `ImageFolder` 需要 `dataset/<子类>/图`；`--dataset` 传父目录 |
| 训练报 `AttributeError: ANTIALIAS` | Pillow 版本问题 —— **已修**（`utils.py` 已换成 `Resampling.LANCZOS`） |
| 训练报 `modified by an inplace operation` | **已修**（`utils.py` 的 `normalize_batch` 改非原地） |
| 量化报 `SavedModel file does not exist` | **已修**（`to_tflite.py` 显式用 `-fdosm` 让 onnx2tf 出 SavedModel） |
| `FileNotFoundError: onnx2tf` | `run_batch.sh` 已把 venv 的 bin 加进 PATH；手工跑时自己加 |
| 想重跑某个配置 | `--force`（默认会跳过已完成的） |
| 表头被当成一个配置 | 已加校验，会自动跳过（表头请用 `#` 注释） |
